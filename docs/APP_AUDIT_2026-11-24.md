## Release blockers / high priority

### 1. Publish ZIP omits all first-view WebP plates — confirmed

Reproduction: `python3 make_publish.py`; inspect `eduverse-publish.zip`. The generated 31,275,825-byte ZIP contains 274 JPEGs but **zero** `assets/2d/rx/` entries, while the current runtime references 278 unique WebPs, across all 266 mapped sections. `make_publish.py` loops over chapter JPEGs only. `src/app.js` prepends the WebPs to the image lists, so they are the initial image, and `src/sciverse.js` renders the initial file; a missing flipbook image is marked missing and degrades to a text panel, not an automatic switch to the JPEG. In the 3D/2D overlay path, an image load failure hides the overlay and may restore 3D. The JPEGs are present as alternate images, but should not be assumed to rescue the first view automatically.

**Action:** package every referenced `assets/2d/rx/` WebP, verify ZIP membership and byte parity against the runtime mapping, then test the extracted ZIP served locally: first views, image cycling, zoom and hotspots. Do not distribute this newly generated ZIP as complete. `qa/audit_draft_integration.py` currently says `ZIP=verified` after checking the JPEGs and HTML; it does **not** check WebP membership, so its pass is not a complete package guarantee. Add a regression test for all referenced runtime assets.

### 2. Science, Hindi/English and visual sign-off — pending

All 266 rollout rows are `AI_DRAFT_REVIEW_PENDING` / `DRAFT_ONLY`. The prior 55-plate work was a thumbnail screening: 14 targeted corrections, 41 thumbnail-only; all 55 still need independent subject-teacher review (`docs/plate_review_55.csv`, `docs/PLATE_REVIEW.md`). That screening was not a full-resolution scientific, Hindi or accessibility audit, and does not establish the quality of the rest of the app. Static/AI illustrations are not evidence of experiments or measurements.

**Action:** review every lesson, explanation, calculation, question and illustration at full size against authoritative curriculum sources; verify bilingual text, hotspot targets, apparatus, safety and diagram meaning. Document reviewer and decision. Particularly inspect gas-delivery/distillation apparatus, movable pulley, meiosis/cells, historical apparatus, `ethanol_oxidation_kmno4`, work-energy and plant/animal classifications. `REVIEW_NEXT_STEPS.md` lists five existing lesson-content concerns (X 1.9 rancidity, 2.5 pH range, 5.5 ATP yield, 8.4 independent assortment and 13.4 biomagnification) and fractional atomic sliders: investigate these as review flags, not as newly proven defects in this audit.

### 3. Requested 288 concepts and nine topic identities — unverified

266 runtime spreads are mapped; `eduverse_topic_audit/CONCEPT_TRACKER_FIRST_PASS.csv` contains 534 provisional rows and is **not** an authoritative list or proof of 288-concept coverage. Nine generic-page topic identities are proposed and their original identities unknown. Class IX Atomic Structure 8.6–8.8 replacement candidates await user review.

**Action:** obtain the intended authoritative 288-concept list; map each concept to its lesson, illustration, interaction and review decision; resolve the nine placeholders and obtain the outstanding replacement approvals. Do not represent 266 spreads or 534 provisional rows as 288 completed concepts.

### 4. Real-browser, device and accessibility regression — unverified

`npm run qa` passed its available checks, but `flipbook_layout.js` **skipped** because Playwright was absent; `label_geometry.js` used static geometry only. `sciverse_smoke.js` uses a simulated DOM/VM: its pass is not a real-browser end-to-end test. A fresh attempt to use a packaged headless Chromium could not launch because the environment lacks `libnspr4.so`, `libnss3.so` and `libnssutil3.so`. Consequently this audit does not certify layout, rendering, interactions or real offline behavior in a browser. Historical browser results in `docs/LAUNCH_AUDIT.md` refer to a different artifact/hash.

**Action:** install a supported Playwright/browser and OS libraries in CI; ensure missing browser prerequisites fail release checks rather than silently skipping. Test all spreads at laptop size and representative phones, plus Hindi/English/both, navigation, page turns, labels, zoom, image cycling, search, quizzes, progress persistence, 2D/3D switching, compiler, exports, slow/missing assets and reload. Test real touch devices, GPUs, browsers, projector readability, keyboard/focus and screen readers. Check whether DOM-overlay labels appear in exports. Verify offline operation of the extracted package and document browser `file://` limitations.

## Other findings

- **Medium — stale publishing guidance:** `publish/PUBLISH.md` says only 201/274 JPEGs have labels and 73 remain unlabeled, but the current metadata audit verifies 274/274 JPEG keys with 516 hotspots. The same guide says ship the full `assets/2d/` directory; the ZIP generator currently fails to do so. Update documentation after the packaging issue is fixed and reconcile dated audit reports.
- **Medium — almost no payload budget headroom:** current HTML is 4,965,562 / 5,000,000 bytes, only 34,438 bytes below the enforced cap (`build.py`). Additional embedded content may break builds; budget or reduce payload before expansion.
- **Medium — deployment assumptions:** HTML embeds runtime libraries and data, but images are external local files. HTML alone is not a complete offline distribution. No service-worker registration was found in `src/`; offline use should not be assumed to mean a previously visited hosted app will work offline. GitHub Pages does not apply the supplied `_headers` or nginx config; verify actual host headers and asset paths. No public deployment was tested.
- **Security / supply chain — limited assessment:** generated CSP uses script hashes, `connect-src 'none'`, and denies framing in the supplied host header; inline styles are allowed for dynamic styles. Header enforcement depends on hosting configuration. `npm audit` on the locally installed dependency resolution reported zero known advisories (including `--omit=dev`) at audit time; this is not a penetration test, does not audit all vendored code or content, and is not a guarantee of safety. `package-lock.json` is ignored, so fresh dependency resolution can vary; consider a committed lockfile and a repeatable dependency/third-party licence review.

## What was checked and what passed

- `npm run qa`: structural syllabus check reports 33 chapters / 266 spreads; 274 JPEGs mapped and present; 310 chapter-qualified WebP placements, 278 unique WebPs, 1,246 WebP bilingual label entries; 516 JPEG bilingual labels. Static geometry covers 552 images / 1,762 hotspot boxes. The metadata parity check covers 18 corrected plates; it does not validate science.
- A freshly generated ZIP passed the existing JPEG-only archive checks. Local HTTP byte parity passed for current HTML, all 274 mapped JPEGs and, in a separate check, all 278 unique referenced WebPs in the repository. This confirms local file serving, **not** browser usability or ZIP completeness.
- `git diff --check` passed. No code or packaging defects were fixed as part of this audit; the generated ZIP and `publish/index.html` are ignored build outputs.
